# Halton-MaskGIT — small 384 / cfg=1.0   LazyMAR 复现 sweep
#   (LazyMAR 的两个缓存一起上: Token Cache + CFG 残差 Cache)
#
# Model    : ImageNet_384_small.pth (79M, 12 层 / 512 dim / 24^2+1=577 token)
# Sampler  : halton, step=32, cfg_w=1.0, fp32, seed=42, global_bsize=32, 50000 imgs
#            —— Halton 顺序 / step gate / 温度 / CFG 与 baseline 完全一致, 未改动。
# Gate     : step 5..30, 两个缓存的 refresh 周期取同一个 N
# Layers   : LAZY_START=3 .. LAZY_END=11 (从 LazyMAR 的打分层一路用到最后一层)
#
# ============================================================================
# 方法 = LazyMAR (ICCV'25) 在 Halton-MaskGIT 上的复现, 两个缓存省的是不同维度
# ----------------------------------------------------------------------------
# (1) Token Cache —— 省 **token**   [LazyMAR/models/basic.py _prune_tokens]
#     partial 步只重算 k_t = ceil(rho_t * 577) 个 token 的 Q/FFN, K/V 走全长
#     per-layer 缓存 (active 行重算后 scatter 回缓存), 双向 attention 的上下文
#     保持完整; 区间出口层用缓存回填 inactive 行; head 也只算 active 行。
#     选点 = TopK(1 - cos(V_l3(t), V_l3(t-1))), **没有任何强制 token**
#     (LazyMAR 里 score[mask_to_pred]=0 的强制保留被去掉 —— 见 lazyvsim sweep 的
#      消融: U_(t-1) 本来就 100% 被打分选中, 而 U_t 落选并不损失 FID)。
#     rho_t = LazyMAR 的 RETAIN_RATIO_SCHEDULE, 64 步表按生成进度重采样到 32 步。
#     实装: HALTON_LAZY_CACHE=1 + HALTON_LAZY_VSIM=1
#
# (2) CFG 残差 Cache —— 省 **batch**  [LazyMAR/models/mar_cache.py forward_mae_decoder]
#     lazy 步只把 [cond ; uncond] 的 **cond 半个 batch** 送进 transformer 主干,
#     uncond 半由 "cond + 上一个整批步记下的 (uncond - cond) 残差" 补出来 ——
#     即 `x = torch.cat([x, x + diff], dim=0)`。
#     残差缓存点取在 transformer 出口 / last_norm 之前 (与 LazyMAR 缓存在 decoder
#     最后一层输出对应), 因此 uncond 分支仍然用它自己的 y 过 AdaNorm 和 head,
#     被跳过的只有主干的 12 层。
#     实装: HALTON_CFG_DELTA=1
#           Network/transformer.py:Transformer.forward + _fit_cond_half
#           Sampler/halton_sampler.py 的 cfg_delta_reuse 门控
#
# N 的语义 (两个缓存取同一个值):
#   Token Cache : gated step 里 counter % N == 0 的步全量刷新 (N<=0 = 永不刷新)
#   CFG 残差    : Token Cache 的 partial 步一律复用残差 (batch 必须保持半份);
#                 只有在 Token Cache 的**全量步**上, 它才按自己的 N 决定刷不刷新。
#                 所以下表里 "半batch步" 总是 >= "partial步"。
#
# 正确性 (python test_cfg_delta.py, 10/10):
#   D1  输入不变时残差重构精确到浮点噪声 floor —— cond Δ=2.09e-07 / uncond Δ=1.94e-07,
#       而"同一份输入按 2B 跑和按 B 跑"的纯 kernel 噪声本身就是 2.09e-07。
#   D2  CFG_DELTA_N=1 (每个整批步都刷新, 从不复用) 与 baseline 逐位一致。
#   D7/D8/D9  两个缓存同开时: 逐步 token 预算与只开 Token Cache 时逐个相同, 打分在
#       半 batch 上做且不再做 cfg_pair 分数平均, kv_miss / restore_miss / score_miss /
#       head_miss / cfg_delta_miss 全为 0。
#   既有方案未受影响: test_lazy_token_cache.py (16/16), test_lazy_vsim.py (9/9)。
#
# 接口: launch/eval_fid_small384_lazymar.sh   (队列: launch/run_lazymar_all_sweeps.sh)
#   HALTON_LAZY_CACHE=1 HALTON_LAZY_VSIM=1 HALTON_LAZY_VSIM_SCHED=lazymar
#   HALTON_LAZY_START_LAYER=3 HALTON_LAZY_END_LAYER=11 HALTON_CACHE_REFRESH_N=N
#   HALTON_CFG_DELTA=1 HALTON_CFG_DELTA_N=N HALTON_CFG_DELTA_START=5
#   保护: cfg_w=0 时报错 (没有 uncond 分支); 与旧的 FFN/ATTN/LAYER delta 缓存组合
#         时报错 (那些缓存在 batch 减半时会静默退化成 0-delta)。

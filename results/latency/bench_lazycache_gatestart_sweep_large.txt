# 读法
# ----------------------------------------------------------------------------
# 1) 成本只由 partial 步数决定, 与 S 的奇偶相位无关。
#    S 从偶数抬到相邻奇数时, 门内第一步的 refresh 相位挪一格 —— refresh 步 -1,
#    partial 步不变, 全量步合计不变。于是 (0,1)/(2,3)/(4,5)/(6,7) 各自成对:
#    理论 FLOPs 差 <0.3%, 实测 latency 差 <0.35% (1180.20/1181.99, 1237.22/1239.91,
#    1294.29/1298.67, 1352.40/1353.94), 都在 baseline 的 ±sd 之内。
#    但 FID 在每一对里都是奇数侧更好 (3.97->3.53, 3.25->2.89, 2.86->2.70, 2.71->2.62)。
#    => 偶数档在 FID-latency 上被同价的奇数档支配, 实际可选点只有 S ∈ {1,3,5,7}。
#
# 2) 达成率随 S 单调上升 (95.1% -> 96.8%)。partial 步越少, 未被 FLOPs 模型计入的
#    固定开销 (gather/scatter、缓存写回、head 的 index_select、python 调度) 在总时
#    间里占比越小, 所以越"省"的档反而越难吃满理论加速。
#
# 3) FID/latency 前沿: S=7 拿到 1.490x 而 ΔFID 只有 +0.074 (2.6153 vs baseline 2.5410),
#    是全表性价比最高的一点; 相对既有默认档 S=5, 慢 4.3% 换 ΔFID -0.080。
#    S=8 比 S=7 慢 4.0% 而 FID 持平 (2.6162 vs 2.6153) —— 被 S=7 完全支配, 门再往右
#    收已经不再买到质量。另一端 S=0/S=1 只比 S=5 快 9%~10%, 却付出 ΔFID +1.27/+0.83。
